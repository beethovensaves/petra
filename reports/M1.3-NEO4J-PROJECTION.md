# M1.3 Neo4j projection and graph-query report

Status: pass
Scope: `M1.3-W09`–`M1.3-W20`, `M1.3-AC02`–`M1.3-AC06`
Date: 2026-09-02

## Outcome

Petra now has a real, visible, rebuildable Neo4j authority-graph read model. An
accepted `ASSERTS` relationship travels through the actual PostgreSQL command,
Approval, event, outbox, authoritative dependency loader, official Neo4j
driver, graph transaction, backend receipt, and PostgreSQL checkpoint path.

The read model is not a second scientific-authority database. Every projected
scientific edge retains an Assertion ID and record hash that the application can
resolve back to PostgreSQL. Neo4j can be deleted without deleting scientific
history.

## Implemented graph surface

| Surface | Result |
| --- | --- |
| Nodes | Project, Work, WorkVersion, Artifact, SourceSpan, and Claim carry stable IDs, revisions, record hashes, and selected visible metadata |
| Relationships | Native typed structural, provenance, bibliographic, representation, and scientific edges carry deterministic edge or Assertion identity |
| Source boundary | SourceSpan selectors and content hashes are projected; selected source text is not duplicated into Neo4j |
| Authority | Applied outbox Claim and Assertion must exactly equal their stored PostgreSQL revision before graph construction |
| Ordering | The Project/projection head accepts only the next target sequence; an exact retry converges and a gap fails |
| Concurrency | Per-node and per-edge identity locks prevent Project streams from racing an older shared revision over a newer one |
| Lookup | Stable node ID and Assertion ID return storage-neutral object views |
| Local graph | Direction, predicate filters, Project scope, deterministic ordering, and 1–100 result bounds are explicit |
| Provenance | One query resolves Work → WorkVersion → `ASSERTS` → Claim → SourceSpan → Artifact |
| Evidence | Only controlled scientific relation classes enter the Claim evidence query; absence returns an empty result |
| Citations | `CITES`/`CITES_AS_BACKGROUND` traversal is directed, breadth-first, deterministic, and bounded to one through six steps |
| Freshness | Projected and observed target positions produce `current`, `catching_up`, or `ahead_invalid` with the exact pending count |
| Rebuild | Project graph state is removed, the complete outbox stream is replayed, and the active Assertion ID is unchanged |

## Real-service proof

`npm run test:neo4j:integration` creates a uniquely named disposable stack with:

- PostgreSQL `18.6`;
- Flyway OSS `13.4.0` applying and validating migrations `V001`–`V008`;
- Neo4j Community `2026.07.1`; and
- official `neo4j-driver` `6.2.0`.

The three-case package run contains two always-on invalid-bound checks and one
cross-database scenario. The cross-database scenario:

1. registers the canonical Project, scholarly identities, verified source and
   parser Artifacts, document structure, SourceSpan, and quarantine evidence;
2. submits, human-approves, and applies the ChangeSet through the real
   PostgreSQL authority repository;
3. projects the emitted `neo4j_graph` outbox record and records its real Neo4j
   bookmark only after graph commit;
4. resolves the trusted `ASSERTS` relationship and provenance path with exact
   PostgreSQL hash parity;
5. exercises object, neighborhood, evidence, citation, and freshness queries;
6. uses separately PostgreSQL-registered quarantine `CITES` and `SUPPORTS`
   proposals as an adapter conformance batch, proving that bibliographic and
   scientific relations remain distinct;
7. refuses an older Claim revision without advancing the Neo4j head;
8. deletes and rebuilds the Project from its complete outbox stream; and
9. confirms the same trusted Assertion ID after rebuild and removes every
   disposable Docker resource.

## Boundary retained

The current production projector accepts the self-contained
`change_set.applied` event defined by M1.2, which promotes one Claim plus its
`ASSERTS` Assertion. The adapter already preserves PostgreSQL-backed `CITES` and
scientific relation types correctly, but normal citation delivery must come
from a future authoritative ingestion event/outbox contract. The test does not
pretend that direct conformance-batch construction is a public mutation API.

The graph has no browser, model, Python-worker, or arbitrary-Cypher mutation
route in Petra. Browser access remains a developer inspection tool. Product
mutations continue through runtime-validated TypeScript commands and
PostgreSQL.
