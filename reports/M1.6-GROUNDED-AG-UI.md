## Outcome

Petra now carries one validated, snapshot-bound scientific synthesis through its production AG-UI interaction path. The server composes the provider-neutral grounded-synthesis executor with the certified Codex subscription adapter, and the official Petra interaction client receives visible retrieval, packet, model, validation, and terminal events.

The live integration used the existing Codex-managed ChatGPT OAuth session. It reported `auth_mode: chatgpt` and `plan_type: prolite`; Petra accepted no API-key option and used no Platform API key.

The public M1 question is deliberately narrow:

> What does the selected study report, and what limits the claim?

It selects the frozen, already-certified M1 packet. This is an executable vertical slice, not an arbitrary-question retrieval planner.

## Runtime path

```text
authenticated AG-UI request
  → grounded_synthesis workflow
  → exact M1 question and certified profile
  → current OAuth account and entitlement checks
  → frozen ContextPacket and EvidencePacket
  → SynthesistGateway policy and certification gate
  → ephemeral read-only Codex App Server turn
  → strict schema and packet-grounding validation
  → Petra rendering with epistemic-origin labels
  → AG-UI terminal result with exact provenance
```

Petra checks the current Codex CLI version, projected provider-schema hash, exact prompt-profile hash, deployment identity, and full model-catalog entry against the recorded active certification before a turn starts. Model, runtime, prompt, schema, catalog, or endpoint-fingerprint drift fails closed and requires recertification.

The assistant text is emitted only after the gateway records a successful ModelCall and all configured validators accept the output. The response restates `H01` with its descriptor once, then separates the source report, Petra's bounded synthesis, unresolved inference, limitations, resolution requirement, and evidence boundary. AG-UI transports these observations; every activity and terminal record has `authority_effect: none`.

## Visible event contract

The successful live run emitted these activity types in order:

1. `petra.retrieval.status` — finding a bounded evidence path;
2. `petra.retrieval.status` — bounded path selected;
3. `petra.evidence_packet.status` — immutable packets ready;
4. `petra.model.status` — certified synthesist running;
5. `petra.model.status` — recorded model call completed;
6. `petra.validation.status` — evidence references and origins validated; and
7. `petra.work_unit.status` — grounded response ready.

The terminal event exposes ContextPacket, EvidencePacket, snapshot, ModelRequest, ModelCall, deployment, certification, output hash, epistemic origins, coverage, phase timings, cost-accounting state, and `authorityEffect: none`. It exposes no credentials or hidden reasoning.

## Cancellation and stream correctness

An explicit Petra cancellation aborts the provider-neutral invocation signal. The Codex adapter translates an in-flight abort into the exact App Server `turn/interrupt` operation; late model output cannot become an accepted response.

The runtime stream also rechecks its event cursor after listener registration and before terminal return. Tests reproduce both event-arrival windows so a fast producer cannot strand the client or make it miss events emitted immediately before completion. Exact replay resumes from the requested sequence without another model call.

The current server interaction store is in memory. `M1.6-W18` completes the production protocol translation, but the persistence portion of `M1.6-AC07` remains open until the grounded terminal is bound to the durable `PetraInteractionRun` repository.
