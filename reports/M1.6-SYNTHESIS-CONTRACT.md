# M1.6 grounded synthesist contract

**Status:** pass for `M1.6-W13`, `M1.6-W15`, and `M1.6-W16`  
**Date:** 2026-09-03  
**Scope:** strict structured output and packet-bound scientific validation

## Outcome

Petra now has a provider-neutral `model-synthesist-output@1.0.0` contract and a
separate domain validator. The contract eliminates a free-form answer envelope:
all material scientific language must occur in a statement with exactly one
epistemic origin.

- `source_report` attributes a statement to source evidence and requires at
  least one exact evidence reference;
- `petra_synthesis` identifies Petra's bounded composition and requires at
  least two exact references; and
- `unresolved_inference` is visibly non-evidentiary and must state what would
  resolve it.

The response also carries one coverage disclosure. It names bounded context
coverage, acknowledges material omissions, reports abstract-only source use,
and reproduces contrary- and qualifying-evidence status.

## Two validation layers

JSON Schema rejects malformed structure, ungrounded source reports, additional
authority fields, and other unregistered output. `GroundedSynthesisValidator`
then resolves schema-valid references against one registered ContextPacket and
EvidencePacket.

For each material source report or Petra synthesis, it verifies:

1. the EvidencePacket belongs to the exact ContextPacket, Project, and graph
   snapshot;
2. evidence is current for that snapshot;
3. every object kind, ID, revision, hash, and selection order exactly matches a
   selected Claim or Assertion;
4. every SourceSpan selection order exactly matches the evidence selection and
   resolves to a selected SourceSpan;
5. the ContextPacket marks each cited scientific record `trusted`; and
6. a `source_report` includes a trusted `ASSERTS` record, while a
   `petra_synthesis` includes at least two exact records and an Assertion.

Coverage values are not model opinions: the validator requires them to equal
the packets' coverage, material-omission, abstract-only, contrary, and
qualifying states.

## Authority boundary

The output schema has no trusted-state, review, ChangeSet, command, graph edge,
or mutation field. A valid response is still generated language, not a Claim or
Assertion and not independent scientific evidence. It may be rendered only
after post-schema packet validation. DraftArtifact authority and revision
semantics remain later M1.8 work.

## Verification

The TypeScript and strict frozen Pydantic contract suites accept the
three-origin fixture and reject a source report with no evidence plus a model
attempt to inject trusted authority. Six domain tests accept and deep-freeze
the valid response and reject:

- an exact-looking ID outside the EvidencePacket;
- source attribution without a trusted `ASSERTS` record;
- changed SourceSpan selection orders;
- false omission acknowledgment;
- repeated statement identity; and
- structurally valid references to quarantined Claim and Assertion records.

The complete repository gate passes with 239 contract, 170 core, 26 adapter,
15 retrieval, two always-on Neo4j, two always-on S3, 16 server, and 25 Python
tests: 495 always-on tests total, with six expected external-service skips.

## Deliberate limits and next slice

Reference validation proves provenance and declared origin, not that arbitrary
natural language perfectly paraphrases its cited evidence. `M1.6-W14` therefore
still needs a frozen synthesist prompt, deterministic evaluation fixtures,
Felicity and scientific-force checks, a role certification, and one recorded
configured ModelRequest and ModelCall. The managed-subscription Codex adapter
can supply that run without an API key once the general synthesist call contract
is added; no extractor certification is reused for synthesis.
