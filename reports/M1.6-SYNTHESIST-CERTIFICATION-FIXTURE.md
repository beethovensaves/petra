# M1.6 synthesist certification fixture

Date: 2026-09-03

## Outcome

Petra now evaluates a model deployment for the synthesist role independently of extractor certification and provider identity. The evaluator issues a schema-valid `model-role-certification@1.1.0` record only from a versioned dataset snapshot, exact deployment, role profile, prompt profile, packet registry, expected outcomes, and observed outputs.

An active result means every case matched its exact expected outcome. It does not mean that a vendor model is generally reliable, that a subscription tier is permanent, or that Petra has granted the output scientific authority.

## What the fixture evaluates

Each case runs the canonical synthesist output schema and Petra's packet-aware `GroundedSynthesisValidator`. A case may also require or forbid specific statement origins and require a minimum number of exact evidence references.

The evaluator distinguishes:

- malformed structured output;
- a citation that does not reproduce the selected packet object;
- other packet, trust, provenance, SourceSpan, and coverage failures reported by the grounding validator; and
- a grounded response that still omits a required epistemic form.

Certification identity binds the deployment, input and output contracts, scope, evaluation dataset and prompt, decision, and invalidation conditions. Reusing an extractor certification or changing any bound component cannot authorize the synthesist gateway.

## Executable evidence

Two new core cases prove that:

1. a three-case fixture can activate only when a valid response preserves all required origins, a malformed response is detected, and an escaped evidence reference is detected; and
2. a schema-valid, packet-grounded response fails certification when it omits the required `unresolved_inference` form.

The complete repository gate passes with 515 always-on tests and six expected service-integration skips.
