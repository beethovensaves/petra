# M1.7 durable interaction replay

Status: pass for `M1.7-EV01`; `M1.7-W12` remains in progress

Scope: successful grounded terminals, process-restart replay, delivery receipts, and the presentation-authority boundary

Date: 2026-09-04

## Outcome

Petra can now restore and replay a completed grounded interaction after the server process restarts. It reads the interaction by its protocol thread and run IDs, verifies the prompt hash when a prompt is supplied, reconstructs the canonical logical event sequence from content-addressed Artifacts, and deterministically translates those events back into the same AG-UI wire presentation.

The restored path does not run retrieval, packet compilation, a model, validation, a command, or a ChangeSet again. It observes the exact existing WorkUnit and records a new delivery receipt. Replaying an interaction therefore remains presentation behavior, not an alternate scientific-authority path.

## Durable sequence

```text
grounded execution and validation
  → persist early logical events as canonical JSON Artifacts
  → append hash-chained InteractionEventRecords
  → complete InteractionRun revision 2 with the early stream head
  → persist or reuse the exact GroundedResponse
  → persist the answer-bearing event suffix
  → advance InteractionRun to revision 3 by stream head only
  → expose answer text
  → record the connection delivery and exact checkpoint
```

Migration V012 permits the final revision only when the prior run is terminal, its lifecycle payload is byte-equivalent in canonical form, and its event count strictly increases. All earlier lifecycle-transition, correlation, feature-manifest, lineage, event-chain, timestamp, and head-hash checks remain in force. A completed run cannot be reopened or assigned a different outcome under the label of replay completion.

## Event identity and AG-UI translation

Petra persists one logical interaction event per sequence position. A logical event may expand into more than one AG-UI event: an activity also emits Petra's registered status event, and a tool proposal expands into start, arguments, and end events. The logical record names the primary AG-UI semantic event, while the canonical JSON payload retains everything needed to derive the complete wire sequence.

Events are canonicalized before their first live publication. Initial and restored delivery therefore have the same nested key order as well as the same values, IDs, timestamps, sequence positions, and metadata. The AG-UI SDK remains behind Petra's adapter; persistence does not adopt the SDK's client state as scientific state.

## Reconnect and delivery behavior

Both interaction endpoints can use durable history:

- `POST /api/interactions/run` treats an existing thread, run, and prompt hash as replay or resume rather than new work;
- `GET /api/interactions/:runId?thread=…&after=…` restores a run that is not present in process memory;
- a client can supply a stable Petra `InteractionConnection` ID, and every completed, aborted, or write-failed delivery records the requested checkpoint, delivered suffix, outcome, and exact WorkUnit observation; and
- the server records an event as delivered only after every AG-UI wire event derived from that logical event has been encoded.

A reused run ID with a different thread or prompt is rejected. A changed HTTP request or trace ID does not make a valid reconnect conflict with its original work.

## Fail-closed behavior

The answer-bearing suffix is persisted before it is published. If suffix persistence fails, Petra emits `GROUNDED_PRESENTATION_PERSISTENCE_FAILED` and emits no assistant text. The server conformance suite proves this ordering.

Interaction payload Artifacts are private generated records. Their rights decisions permit storage and parsing but forbid remote model transmission, public quotation, and redistribution. They are presentation evidence, not scientific evidence, and every replay receipt states that authority was not reapplied, commands were not reexecuted, and durable work was not cancelled.

## Deliberate limits

This increment covers completed grounded interactions. `M1.7-EV02` subsequently made the prompt-bound, cancellable WorkUnit durable before provider execution, but progress events remain process-local until the grounded terminal is assembled; Petra does not yet resume an active model turn after a process crash. Non-grounded fixture and review-interrupt presentation history is not routed through this terminal recorder. Explicit cancellation still needs to become a durable, authorized WorkUnit command rather than only an in-process abort.

Those limits keep `M1.7-W12` in progress. The next backend stage is explicit durable cancellation. The design worktree separately owns reconnect indicators, retry affordances, stopped-state presentation, and all other visual behavior.
