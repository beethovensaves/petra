# M1.6 retrieval foundation

**Status:** pass for `M1.6-W01`–`M1.6-W05`  
**Date:** 2026-09-03  
**Scope:** model-free identity, lexical, graph-neighborhood, provenance, and hybrid retrieval

## Outcome

Petra now has a small graph-guided retrieval boundary without a retrieval
framework or generative-model dependency. Known identities and provenance
requests go directly to `AuthorityGraphStore`. Open-text questions first
produce bounded lexical candidates and then join those candidates to exact
graph objects before any local evidence neighborhood is returned.

The slice implements:

- `M1.6-W01`: canonical object retrieval by Project and stable identity;
- `M1.6-W02`: deterministic, title-weighted BM25 candidates with explicit
  scorer, Project, object-kind scope, scoped corpus size, rank, score, matched
  terms, authoritative revision, and record hash;
- `M1.6-W03`: bounded, direction- and predicate-explicit typed graph
  neighborhoods;
- `M1.6-W04`: exact Assertion-to-WorkVersion-to-Work-to-Claim-to-SourceSpan-to-
  Artifact provenance through the existing graph port; and
- `M1.6-W05`: the versioned `petra-bounded-lexical-graph@1.0.0` recipe.

## Authority and failure semantics

The lexical index is a candidate generator, not scientific authority. A hybrid
candidate is usable only when Neo4j returns the same stable node kind,
authoritative revision, and record hash recorded by the lexical projection.
Missing graph objects, identity mismatches, and stale lexical revisions are
reported as typed omissions. Petra expands no neighborhood for an omitted
candidate.

Every route is bounded: queries contain at most 2,000 characters, lexical
results at most 25 candidates, and graph expansion at most 50 neighbors per
candidate. The M1 recipe defaults to 10 lexical results and eight neighbors per
candidate. Its requested direction and predicate set are reproduced in the
result so later packet compilation can explain the retrieval scope.

## Architectural judgment

`ScientificLexicalIndex` is provider-neutral. The in-memory implementation fixes
deterministic scoring and test behavior but does not commit Petra to an
in-memory production corpus. A later PostgreSQL full-text adapter can implement
the same port after representative corpus and latency measurements exist.
`AuthorityGraphStore` remains the graph boundary; the retrieval package neither
imports the Neo4j driver nor creates another scientific state store.

No model adapter, prompt, embedding service, or API credential participates in
this slice. This is both a latency path and an epistemic boundary: stable
identity and provenance do not need probabilistic interpretation.

## Verification

Six new tests cover:

1. identity retrieval with zero lexical calls;
2. deterministic Project- and kind-scoped lexical ranking;
3. malformed, duplicate, and over-limit refusal;
4. bounded predicate-explicit graph expansion;
5. exact provenance with zero lexical calls; and
6. current-revision hybrid admission plus visible stale and missing omissions.

Together with the nine frozen Paper Trail cases, all 15 retrieval tests pass.
The complete repository gate passes with 235 contract, 158 core, 26 adapter,
15 retrieval, two always-on Neo4j, two always-on S3, 16 server, and 25 Python
tests: 479 always-on tests total, with six expected external-service skips.

## Deliberate limits and next slice

This result does not establish retrieval quality over a representative Petra
corpus, compare dense or HippoRAG2 challengers, implement a production
PostgreSQL lexical adapter, compile model context, or generate an answer. Those
claims would be premature.

The next slice is `M1.6-W06`–`M1.6-W12`: compile the accepted hybrid result into
immutable ContextPacket and composition-specific EvidencePacket records with
snapshot identity, contrary evidence, processing depth, explicit omissions,
dependency hashes, and an exact token budget.
