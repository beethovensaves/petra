# M1.5 managed-subscription extractor certification

- **Date:** 2026-09-03
- **Roadmap work:** `M1.5-W13`, `M1.5-W18`
- **Provider:** Codex App Server with managed ChatGPT OAuth
- **API key:** Not used or required
- **Candidates:** GPT-5.6 Luna and GPT-5.6 Terra
- **Result:** Terra active; Luna failed and remains inactive

## Outcome

Petra ran its `petra-live-extractor@1.1.0` scientific extraction route twice against both picker-visible subscription models. Each candidate received the same prompt profile, provider schema, three source passages, SourceSpan identities, semantic expectations, read-only sandbox, no-tool policy, low reasoning effort, and client-enforced output bound.

GPT-5.6 Terra passed all three cases on both runs. Each run then routed a fourth extraction through the real provider-neutral `ModelGateway`, passed canonical schema and source-grounding validation, and produced one Claim–`ASSERTS` proposal whose Claim and Assertion remained `machine_checked` in `quarantine`.

GPT-5.6 Luna returned canonical, exactly quoted, SourceSpan-grounded output for every case but failed one bounded semantic expectation on both runs. It classified “a measurable improvement” as `comparative`; suite 1.1.0 currently requires `descriptive` for that case. That choice is scientifically defensible, but it does not match the frozen expectation, so Petra records Luna as failed rather than changing the fixture after seeing the answer. A future fixture revision may review that taxonomy prospectively and would require every affected deployment to recertify.

## Provider-schema calibration

An initial pre-certification attempt failed before model execution because the Responses structured-output boundary required explicit primitive `type` declarations beside `const` fields. Both candidates received three HTTP 400 `invalid_json_schema` outcomes; neither was activated and no proposal was created.

Petra corrected the provider projection to:

- add explicit primitive types only for the strict subscription schema;
- retain only canonically required properties in strict object definitions;
- keep array sizes bounded; and
- independently validate every returned object against Petra's complete canonical contract.

The correction narrows the model's generation grammar. It does not weaken canonical validation, change authority, or conceal the failed calibration attempt. The local provider projection retains its prior shape, so this correction does not silently invalidate Qwen's recorded route.

## Scientific boundary

Terra is eligible only for the exact extractor role and certified scope. Its output still enters quarantine and cannot directly create a trusted Claim, Assertion, ChangeSet, Approval, or Neo4j edge. Subscription-model agreement with Qwen is a provider comparison, not independent scientific corroboration.

This result closes the mixed-provider `M1.5-W13` gate: Petra now has one active local open-weight extractor and one active managed-subscription extractor behind the same validation, proposal, review, and authority contracts. It does not certify Terra for criticism, synthesis, conversation, experimental interpretation, or any other future role.

The complete repository verification gate passes with 473 always-on tests across contracts, core, adapters, retrieval, Neo4j, S3, Hono, and Python. Six external-service-only cases remain intentionally skipped in their always-on suites.
