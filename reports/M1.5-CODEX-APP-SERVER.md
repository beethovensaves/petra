# M1.5 Codex App Server subscription-provider report

- **Date:** 2026-09-03
- **Roadmap work:** `M1.5-W17`
- **Decision:** [D017](../decisions/D017-codex-app-server-subscription-provider.md)
- **Result:** Adapter and live managed-session smoke test pass
- **Scientific extraction status:** Not certified; not eligible

## Outcome

Petra now has a first-class Codex subscription provider that is separate from its OpenAI Responses API and local open-weight model adapters.

When enabled, the Node server starts `codex app-server --listen stdio://` as an owned child process. The adapter uses newline-delimited JSON over stdio, completes one stable `initialize`/`initialized` handshake, correlates requests and responses, bounds messages, times out missing responses, surfaces protocol failures, and closes the sidecar with Petra.

The current application boundary supports:

- credential-free account status;
- managed ChatGPT browser and device-code login ceremonies;
- cancellation of pending managed login;
- thread creation under Petra's server-owned workspace root;
- text turns, model and effort selection, and turn interruption;
- explicit command and file-change approval decisions; and
- provider diagnostics that keep scientific extraction disabled.

Petra exposes none of the adapter's credential storage. It does not read `auth.json`, query a keychain, accept ChatGPT tokens, or implement the experimental `chatgptAuthTokens` refresh flow. Account responses omit email. The OpenAI API key remains the responsibility of the separate Responses adapter.

## Event boundary

`CodexEventTranslator` consumes stable App Server notifications and requests. It emits:

1. standard AG-UI run, assistant-message, tool-call, activity, error, and completion events; and
2. provider-neutral `PetraAgentRuntimeEvent` values suitable for later durable workflow and graph projections.

Every graph-runtime event has `scientificAuthorityEffect: "none"`. Provider thread, turn, item, and approval identities remain distinct from Petra request, trace, WorkUnit, and ModelRequest identities.

Command execution, file change, MCP, collaboration, search, and image-view items are visible as tools. Approval requests are visible activities and remain pending until an authenticated Petra command resolves them. Raw reasoning deltas are deliberately omitted from the assistant stream.

## Security and authority controls

- `experimentalApi` is explicitly false.
- Only `chatgpt` and `chatgptDeviceCode` login types are callable.
- A server request for external-token refresh receives a refusal.
- Unsupported server-initiated capabilities fail closed.
- Managed login URLs must use HTTPS and expected ChatGPT/OpenAI origins.
- HTTP clients cannot supply `cwd`; Petra fixes the workspace root.
- The initial HTTP surface rejects `danger-full-access`.
- Provider status, login, conversation, interruption, and approval routes remain behind Petra's bearer-authenticated `/api` boundary.
- A Codex event cannot write PostgreSQL scientific authority or Neo4j state.

## Executable evidence

Always-on adapter cases cover:

- handshake order and stable-only capability declaration;
- account redaction;
- both managed login ceremonies;
- rejection of externally supplied authentication tokens;
- bounded thread and turn requests;
- approval presentation and resolution;
- external-token refresh refusal;
- timeout and transport failure;
- AG-UI and graph-runtime message, tool, approval, and terminal translation; and
- omission of raw reasoning output.

Always-on Hono cases cover:

- authenticated account and managed-login routes;
- rejection of external-token fields;
- server-owned workspace root;
- rejection of `danger-full-access`;
- bounded turn and approval commands; and
- visible provider-unavailable behavior.

The live command is:

```sh
npm run test:codex-app-server:integration
```

It starts a real sidecar, reads only the adapter's redacted account summary, creates an ephemeral read-only thread, requests a no-tool marker response, waits for streamed completion, verifies AG-UI and graph-runtime translation, and closes the sidecar.

Observed on 2026-09-03:

- Codex CLI: `0.151.0`;
- authentication: managed ChatGPT session;
- entitlement-selected deployment: GPT-5.6 Sol through the OpenAI Codex provider;
- turn: completed;
- translated AG-UI events: 13;
- translated graph-runtime events: 13; and
- scientific authority effects: 0.

The complete repository verification gate also passes: 468 always-on tests across contracts, core, adapters, retrieval, Neo4j, S3, Hono, and Python, with the six expected external-service-only cases skipped in their always-on suites.

The integration command needs normal access to Codex-owned local state and the OpenAI service. A filesystem-restricted test sandbox cannot initialize Codex's SQLite state under its own home directory; that is an environment restriction, not a reason for Petra to read or relocate credentials.

## What this does not prove

The smoke test does not prove that:

- Codex is certified for extraction, criticism, synthesis, or conversational scientific assistance;
- the entitlement-selected model is stable or exactly replayable;
- a ChatGPT subscription provides arbitrary Responses API access;
- a subscription call has a directly comparable metered API cost;
- a Codex and OpenAI API answer are independent scientific evidence; or
- one developer session can be shared in a hosted or public Petra deployment.

The OpenAI Responses API extractor certification remains the only unfinished `M1.5-W13` gate. Hosted identity and tenancy remain later decisions.
