# M1.5 durable AG-UI review interrupt report

Status: pass

Scope: `M1.5-W16`, `M1.5-AC03`, and `M1.5-AC06`

Date: 2026-09-02

## Outcome

Petra can now present one exact evidence-promotion ChangeSet as an AG-UI review
interrupt and resolve the researcher's response through
`executeReviewDecisionPlan`, the same command executor used by direct review.
The interaction protocol gathers and transports the decision; it cannot grant a
capability, construct its own authority context, or write trusted evidence.

An accepted fixture follows this path:

```text
durable pending InteractionInterrupt
  → Petra review presentation
  → AG-UI custom event and standard interrupt outcome
  → closed review-response contract
  → authenticated actor and capability context
  → exact interrupt and ChangeSet comparison
  → immutable responded InteractionInterrupt revision
  → SubmitChangeSet → RecordApproval → ApplyChangeSet
  → trusted Claim and ASSERTS revisions
```

The protocol boundary and the scientific command boundary remain independently
replaceable. Petra core imports no AG-UI types.

Server-side JSON Schema validation is exported through
`@petra/adapters/server`; the browser-facing adapter does not import the
filesystem-backed contract registry. The production workbench build therefore
returns to 374 transformed modules with no Node compatibility warnings. The
AG-UI distribution chunk is 220.83 kB raw and 49.90 kB gzip in this fixture,
about 0.56 kB raw and 0.19 kB gzip above the preceding model-gateway build.

## Response contract

`petra.review-interrupt-response@1.0.0` contains only:

- a client response identity for retry correlation;
- exact Project and canonical InteractionRun identities;
- the interrupt ID, revision, and content hash;
- the ChangeSet ID, revision, and content hash;
- `accept` or `reject`;
- the researcher's rationale; and
- the stated decision time.

The payload has no actor, capability, Approval, command, graph operation, or
authority field. The server supplies the authenticated human actor and
capability grant. A rejected fixture proves that adding client-asserted actor or
capability fields fails the canonical schema.

The AG-UI `RUN_FINISHED` interrupt carries a response schema whose constant
references match the presented durable records. The registered
`petra.review.interrupt` custom event remains an authority-free notification;
the exact revision references are also carried in the standard interrupt
metadata used by Petra's adapter.

## Resolution and recovery rules

`DurableReviewInterruptCoordinator` verifies, in order:

1. the protocol run is bound to one registered presentation;
2. the exact pending interrupt revision still exists;
3. its canonical InteractionRun has the expected Project, protocol run,
   authenticated actor, and capability context;
4. its response schema is the accepted Petra review-response schema;
5. the response repeats the exact interrupt and ChangeSet references;
6. server policy authorizes that actor, capability, decision, and ChangeSet;
7. the generated direct-review plan preserves those exact inputs; and
8. the response Artifact identifies the canonical response bytes.

The responded interrupt revision is recorded before command execution and
labels its effect `command_input_only`. If execution is interrupted after that
record, an exact retry rebuilds the same command plan and continues through its
idempotent command IDs. A different second response cannot replace the recorded
decision. Replaying the exact response does not append another domain event,
outbox record, command execution, or evidence revision.

Malformed and incomplete payloads fail at the adapter contract. Stale
references and conflicting responses fail at the coordinator. Authentication
and capability denials occur before response recording or command execution.

## Limits

The HTTP fixture uses an in-memory evidence and interaction repository so the
official client/server protocol can be tested without coupling Hono to a
database. A separate integration case runs the same coordinator with the real
PostgreSQL interaction and ChangeSet repositories. Hosted authentication still
needs to map a session to Petra's actor and capability records; the current
server fixture uses a configured test identity.

This slice supports accept and reject. A correction remains a separate,
source-grounded proposal and review plan rather than an untyped `revise`
response. No live model quality is claimed.
