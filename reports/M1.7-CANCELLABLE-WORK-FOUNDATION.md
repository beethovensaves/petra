# M1.7 cancellable work foundation

Status: pass for `M1.7-EV02`; `M1.7-W12` remains in progress

Scope: prompt identity, pre-execution WorkUnit persistence, and cache separation

Date: 2026-09-04

## Outcome

Petra now creates the grounded interaction's WorkUnit before retrieval or model execution. The WorkUnit is no longer a retrospective terminal record marked atomic: it is a real, cancellable orchestration aggregate that exists while work is running.

The exact authenticated prompt is stored as a private content-addressed Artifact. Its manifest and rights decision permit the requested private model-assisted workflow but prohibit indexing, embedding, public quotation, and redistribution. The WorkUnit input manifest binds those exact bytes before it enters the queue.

## Lifecycle

```text
authenticated research prompt
  → private prompt Artifact, manifest, and rights decision
  → WorkUnit requested revision 1
  → WorkUnit queued revision 2
  → WorkUnit running revision 3, cancellation_policy: cancellable
  → bounded retrieval and certified synthesis
  → WorkUnit completed revision 4
  → completed InteractionRun and GroundedResponse
  → durable answer-bearing presentation
```

The first WorkUnit activity is visible before retrieval begins and carries the real running revision. A retry with the same run and prompt reuses the exact durable WorkUnit; a different prompt cannot bind to it.

## Cache separation

The interaction WorkUnit uses `cache_mode: disabled`. It identifies one user's run and must retain its own lifecycle, resource control, and cancellation history.

GroundedResponse reuse remains independent. It still requires the exact ContextPacket, EvidencePacket, authority snapshot, model request and call, deployment, role certification, output hash, and dependency set. A new interaction can therefore receive a reused validated response while owning a new non-cacheable WorkUnit and InteractionRun. This avoids treating a cached answer as if the new interaction's operational work never existed.

## Executable evidence

- The complete repository gate passes with 546 always-on tests and seven expected service skips, including the production workbench build.
- The core suite passes 190 tests, including a new case proving that a non-cacheable interaction WorkUnit can bind a reusable GroundedResponse without weakening the response cache key.
- A disposable PostgreSQL 18.6 database applies all 12 migrations and passes 56 repository cases. The grounded-terminal case observes running revision 3 before persistence, requires `cancellation_policy: cancellable`, and then completes the same WorkUnit at revision 4.
- The managed-ChatGPT integration uses the existing OAuth session and durable model cache with no API key. Its AG-UI activity sequence begins with `petra.work_unit.status`, the terminal binds the same WorkUnit revision 4, and process-restart replay remains exact across 17 logical events.

## Remaining boundary

The existing HTTP stop route still invokes an in-process cancellation flag. This stage deliberately does not relabel that behavior as durable cancellation. The next stage must persist an authenticated, idempotent cancellation command, atomically advance the running WorkUnit to cancelled, interrupt the provider turn, record the cancelled interaction presentation, and prove that a connection abort performs none of those actions.
