# M1.4 Docling worker and SourceSpan report

Status: pass
Scope: `M1.4-W06`–`M1.4-W12`, `M1.4-SS01`–`M1.4-SS06`,
`M1.4-AC01`–`M1.4-AC05`
Date: 2026-09-02

## Outcome

Petra now turns one exact, rights-approved scholarly PDF into a local parser
Artifact and a quarantine-only document proposal. The proposal contains a
ParsedDocument, ordered StructuralBlocks, compound SourceSpans, and explicit
diagnostics. It cannot write PostgreSQL or Neo4j, create a trusted Claim, or
grant itself scientific authority.

The calibrated Wilkinson et al. PDF produces nine pages, 116 blocks, and 116
SourceSpans. Both frozen scientific targets resolve to the expected original
pages. The document is intentionally marked `partial`: Docling misorders four
subsets of the FAIR-principles box, omits four multipage items from automatic
span generation, and does not resolve the detected figure's caption.

## Boundary implemented

| Boundary | Executable behavior |
| --- | --- |
| Input identity | The worker validates the shared job schema and RFC 8785 content hash before constructing its strict Pydantic view. |
| Scoped reads | One binding index names the only five readable inputs. Paths must resolve below the explicit fixture root; Artifact bytes and all record snapshots must match their manifest. |
| Rights | Artifact, ArtifactManifest, RightsDecision, and WorkVersion must form one chain, and the exact copy must have verified parse permission. |
| Parser identity | Docling is pinned to 2.121.0. The Petra recipe disables OCR and optional enrichments for the born-digital fixture and records its exact configuration hash. |
| Model identity | Heron and TableFormer revisions are recorded; four required local files are SHA-256 checked before every run. The model cache is disposable and not committed. |
| Connectivity | Hugging Face and Transformers offline flags are set, socket connection entry points are denied during conversion, remote services and external plugins are disabled, and the output reports no network activity. |
| Text fidelity | Native Docling output remains unchanged. Where Docling separates a PDF ligature into tokens, Petra accepts geometry-bounded embedded text only when its alphanumeric sequence matches, and records the recovery on the SourceSpan. It does not guess word boundaries. |
| Source location | Every emitted text span has Artifact and parser-run identity, page geometry, full-block Unicode code-point offsets, exact selected-text hash, structural path, block identity, and parser/normalization versions. |
| Output authority | The worker atomically stages files and a content-bound output manifest. The TypeScript control plane rechecks schemas, hashes, output slots, authority links, reading order, page bounds, text offsets, and selector evidence before accepting the bundle for quarantine. |
| Failure | A malformed but correctly manifested PDF returns `DOCLING_CONVERSION_FAILED`, produces no parse bundle, and leaves trusted stores untouched. |

## Reproducibility proof

Run:

```sh
npm run models:docling
npm run test:docling:integration
```

The first command downloads model assets into ignored `.cache/docling/models`
and verifies their pinned hashes. The integration command then:

1. re-verifies the four model files;
2. builds the TypeScript contract and core packages;
3. executes the worker twice with offline flags and the frozen input manifest;
4. validates each output with Python's shared registry and the TypeScript
   contract and document registries;
5. grounds the broad machine-actionability passage on page 1 and the
   “not a standard or specification” qualification on page 5;
6. compares both executions' ParsedDocument, StructuralBlock, and SourceSpan
   identities; and
7. manufactures an identity-consistent malformed Artifact and proves typed,
   proposal-free failure.

Attempt timestamps, timings, and measured use are observations and may differ.
They do not enter structural identity. The source hash, parser recipe, Docling
version, model revisions, adapter version, recovered text, geometry, and
selector material do.

## Abstract-only control

Parsing does not produce scientific Claims. The previously established Claim
proposal boundary carries the depth restriction: an `abstract_only` source may
ground only a broad descriptive, comparative, or theoretical Claim. Detailed
or causal proposals fail with `ABSTRACT_SCOPE_VIOLATION`. Acquiring full text
later requires a new source-grounded proposal; it cannot silently upgrade the
old Claim.

## Known limits retained

- This is one born-digital, English, peer-reviewed PDF. Scanned documents, OCR,
  actual tables, formula recovery, other scripts, and hostile files need their
  own fixtures before support is claimed.
- Docling's Box 2 order is not silently rewritten. Later review or a better
  adapter may supersede the partial parse while preserving this parser run.
- The job timeout is passed to Docling and measured resource limits fail the
  attempt after processing. They are not kernel-enforced CPU or memory
  isolation. A managed execution sandbox remains a later experiment-stage
  decision.
- The current socket denial covers Python connection entry points during the
  parser call and the integration runs in offline mode. Strong process-level
  egress isolation belongs in deployment infrastructure.
- Parser products are staged on the local filesystem in M1.4. The existing
  ArtifactStore and PostgreSQL repositories will receive them only through a
  later TypeScript acceptance command, never from this worker.
