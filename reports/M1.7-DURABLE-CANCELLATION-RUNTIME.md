# M1.7 durable cancellation runtime

Status: pass for `M1.7-EV04`; `M1.7-W12` remains in progress

Scope: HTTP command, runtime race control, provider interruption, cancelled interaction replay

Date: 2026-09-04

## Outcome

Petra's stop endpoint now resolves a protocol run to its exact durable
WorkUnit and invokes the accepted cancellation command boundary. The runtime
waits for pre-execution WorkUnit registration when necessary, commits the
cancellation first, and only then aborts the active grounded-synthesis signal.
The Codex adapter already translates that signal into App Server turn
interruption.

The endpoint requires a canonical Petra command ID, accepts an optional
researcher-readable reason, and returns the cancellation receipt ID and hash
with the resulting WorkUnit revision. Exact retries return the existing effect
without advancing work again. The production terminal preserves the original
command time across process-level retries, so a lost HTTP response does not
turn a retry into conflicting input.

## Ordering and failure behavior

```text
POST /api/work-units/:runId/cancel
  → resolve the active protocol run
  → await its exact running WorkUnit binding
  → commit CancelWorkUnit + cancelled revision
  → abort the provider signal
  → prepare RUN_ERROR WORK_UNIT_CANCELLED
  → persist the complete cancelled interaction event chain
  → publish the terminal AG-UI event
```

Invalid IDs, empty or oversized reasons, terminal runs, stale WorkUnit
references, wrong capabilities, and conflicting command reuse fail before
provider interruption. If cancelled-interaction persistence fails after the
WorkUnit was cancelled, Petra emits the distinct
`GROUNDED_CANCELLATION_PERSISTENCE_FAILED` outcome rather than claiming that
restart replay is available.

Closing or losing one AG-UI connection still invokes only the delivery path.
It does not call `CancelWorkUnit`, abort the provider, or change scientific
authority. The durable WorkUnit may finish while that connection is absent.

## Executable evidence

- All 29 server conformance cases pass. They prove cancellation persistence
  precedes provider abort, cancelled presentation persistence precedes terminal
  publication, no answer text escapes, and a delivery abort issues zero
  cancellation commands while work completes.
- A clean PostgreSQL 18.6 database applies all 13 migrations and passes all 59
  repository cases. The production terminal stores a cancelled WorkUnit,
  receipt, `InteractionRun`, and exact event chain, then restores the cancelled
  outcome after restart with no `GroundedResponse`.
- A retry with the same command identity but a later transport-request time
  reuses the original durable command and returns `applied: false`.
- A focused core race test issues stop before WorkUnit registration completes,
  proves the provider observes abort only after the durable command, and proves
  a cancelled-history failure cannot emit either answer text or a misleading
  `WORK_UNIT_CANCELLED` replay claim.
- The complete repository gate passes with 552 always-on tests and seven
  expected service skips, including lint, typechecks, and the production
  workbench build.

## Remaining boundary

The backend contract for successful and cancelled grounded-run replay is now
available to the design worktree. `M1.7-W12` remains open for workbench wiring,
visible reconnect states, and the user-facing stop/retry behavior. Recovery of
arbitrary active work after a process crash remains a later scheduler/lease
concern; it is not conflated with reconnecting a client stream.
