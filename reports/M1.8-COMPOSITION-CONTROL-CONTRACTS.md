# M1.8 composition control contracts

Status: pass for `M1.8-EV01`; `M1.8-W01` and `M1.8-W02` remain in progress

Scope: CompositionRequest, CompositionPlan, cross-language parity, and in-memory invariant gate

Date: 2026-09-04

## Outcome

Petra now records why a scientific artifact was requested before it plans or
generates prose. The immutable `petra.composition-request` contract binds the
research objective, subjects, audience, output shape, citation preferences,
evidence namespaces, inference policy, desired depth, capability, privacy,
budget, approval, OutputProfile, Felicity contract, and exact project snapshot.
It explicitly cannot become scientific authority or authorize publication.

The immutable `petra.composition-plan` contract makes the intended path from
evidence to language inspectable before drafting. Ordered sections contain
ordered moves whose evidence, origin, scientific force, citation obligation,
and limitations are separate fields. “Petra inference” remains an origin; it
is not treated as a scientific force or a numerical confidence level.

## Runtime invariants

The composition registry now refuses a plan unless it:

- reproduces the exact registered CompositionRequest, EvidencePacket, Project,
  and snapshot;
- uses unique IDs and contiguous visible positions for sections and moves;
- reproduces exact EvidencePacket selections rather than accepting plausible
  object IDs;
- stays within the request's source, inference, researcher-material, and
  scientific-force permissions;
- names only existing moves when support remains unresolved; and
- occurs after its request and EvidencePacket.

A DraftArtifact now also refuses an absent, blocked, or drifted request/plan
pair. Its artifact kind, semantic format, language, OutputProfile, Felicity
contract, EvidencePacket, and snapshot must agree with those controls. The
existing draft fixture now binds the real canonical hashes of the accepted
request and plan instead of placeholder identities.

## Executable evidence

- JSON Schema accepts the canonical request and ready plan while rejecting a
  request that claims publication authority and a source-report move without
  its required citation.
- Generated TypeScript declarations and strict Pydantic models reproduce the
  same accepted fixtures without mutation.
- Core tests prove immutable/idempotent registration and reject evidence drift,
  forbidden inference, excess scientific force, non-contiguous ordering, and
  DraftArtifact control drift.
- The complete repository gate passes with 563 always-on tests and seven
  expected service skips, including lint, strict TypeScript and Python checks,
  the frozen retrieval benchmark, and the production workbench build.

## Remaining boundary

`M1.8-W01` and `M1.8-W02` stay in progress until these records have durable
PostgreSQL storage and the grounded-response path compiles them automatically.
The next backend increment adds that persistence and exact snapshot/evidence
rehydration. Draft generation and deterministic Markdown, LaTeX, and BibTeX
rendering follow only after the durable control chain exists.
