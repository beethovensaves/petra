# M1.0 AG-UI and Hono conformance

- **Recorded:** 2026-08-28
- **Decision:** Retain Hono; do not activate Fastify
- **Scope:** `M1.0-W10`–`M1.0-W14` and `D014-HC01`–`D014-HC10`
- **Runtime:** Node 24.20.0, npm 11.19.0

## Result

The M1.0 boundary fixture passes all ten executable checks. The official AG-UI `HttpAgent` completes against the Hono route without a protocol workaround, and the official encoder's bytes pass through once, in order. Hono remains confined to the Node HTTP application; AG-UI remains confined to Petra's adapters and the lazily loaded workbench integration.

This result certifies the application shell and interaction boundary. It does not certify model-backed research, PostgreSQL restart recovery, public authentication, or production-scale scientific workloads. Those depend on later M1 slices and cannot be inferred from a deterministic in-memory fixture.

## Protocol fixture

The registered success sequence is:

```text
RUN_STARTED
STATE_SNAPSHOT
ACTIVITY_SNAPSHOT
CUSTOM petra.work_unit.status@1
TOOL_CALL_START
TOOL_CALL_ARGS
TOOL_CALL_END
TEXT_MESSAGE_START
TEXT_MESSAGE_CONTENT
TEXT_MESSAGE_END
RUN_FINISHED
```

The review fixture emits `CUSTOM petra.review.interrupt@1` and an AG-UI interrupt outcome. Direct review and assistant-mediated review resolve through the same idempotent Petra command method. A network abort stops delivery; only `/api/work-units/:runId/cancel` requests cancellation.

## Client cost and chunking

The production Vite build separates the interaction dependency from the initial workbench:

| Asset | Minified | Gzip | Loading point |
| --- | ---: | ---: | --- |
| Initial workbench JavaScript | 288.39 KB | 91.58 KB | Initial page |
| Lazy AG-UI and Petra adapter chunk | 220.27 KB | 49.71 KB | First research run |
| Workbench CSS | 4.62 KB | 1.65 KB | Initial page |

The reproducible isolated comparison in `experiments/m1-boundary` measures the AG-UI-backed client at 228,683 raw bytes and 52,525 gzip bytes. Against its 74-byte interface baseline, the incremental cost is 228,609 raw bytes and 52,433 gzip bytes. The Vite split prevents that cost from delaying the first workbench render; later measurements should decide whether narrower imports or another SDK release materially reduce it.

Run the measurements with:

```sh
npm run test:server
npm run measure:m1-boundary
```

## Next boundary

M1.1 should define `PetraInteractionRun`, replay records, WorkUnit, ModelRequest, command, and interrupt identities through the canonical JSON Schema path. M1.2 should then persist those records and prove restart recovery. Real retrieval and model latency must be measured separately; the deterministic transport numbers above are the baseline against which that later cost becomes visible.
