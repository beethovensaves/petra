# M1.6 retrieval floor record

Status: pass

Scope: `M1.6-W17`

Date: 2026-09-04

## Outcome

Petra now has a committed, content-hashed retrieval floor that places the frozen Paper Trail result beside `petra-bounded-lexical-graph@1.0.0`. Both routes receive the same 50-work abstract-only snapshot, the same query, the same eight-result limit, and the same title and abstract text.

The result is intentionally a regression and graph-admission record, not a retrieval-quality leaderboard.

The routes returned the same eight Work IDs in the same order with the same four-decimal scores. Petra admitted all eight lexical candidates against matching graph identities and revisions, reported no omissions, and returned at most eight citation neighbors per candidate. The frozen record is `experiments/retrieval/m1-floor-record.json`, with content hash `sha256:c5fcac247ddc00610e9b133c6c62b9ec8629629145046a3856cc86fd4e22c98d`.

This parity is expected: Petra deliberately preserved the Paper Trail tokenizer and scoring floor before adding graph admission. Its value is detecting accidental ranking or scope drift while the retrieval architecture evolves.

## Scientific and evaluation boundary

The corpus has one discovery query, no independent relevance labels, abstract-only content, incomplete citations, and known metadata anomalies. Therefore the record declares all of the following false:

- representative relevance judgments exist;
- retrieval-quality ranking is permitted;
- latency ranking is permitted; and
- the retrieved records are admissible as detailed scientific evidence.

The `CITES` neighborhood remains bibliographic. It does not become `SUPPORTS`, agreement, quality, currency, or scientific authority. The benchmark graph is deterministic and in memory so it can verify recipe semantics; it does not claim Neo4j production latency.

## Challenger gate

Dense retrieval, community summaries, HippoRAG2, and other graph-retrieval methods remain named candidates rather than implied winners or losers. Petra will rank them only after the evaluation has:

1. a representative multi-domain corpus;
2. a frozen query set;
3. independent relevance judgments;
4. quality metrics with uncertainty;
5. one latency and cost measurement protocol; and
6. identical rights and evidence constraints across routes.

That gate preserves room for better retrieval without allowing a single convenient fixture to harden an architectural choice.

## Reproduction

Regenerate the deterministic record with:

```sh
npm run benchmark:retrieval:m1-floor
```

Verify the committed bytes without replacing them with:

```sh
npm run benchmark:retrieval:m1-floor:check
```

The check is part of `npm run verify`. It independently executes the preserved Paper Trail route, verifies its earlier expectations, runs Petra's hybrid recipe, checks rank and score parity, checks graph admission, and compares the result with the committed artifact.
