# M1.7 durable cancellation ledger

Status: pass for `M1.7-EV03`; `M1.7-W12` remains in progress

Scope: authorized command contract, atomic WorkUnit transition, and immutable receipt

Date: 2026-09-04

## Outcome

Petra can now cancel a running WorkUnit through a durable, authorized, and
idempotent command. PostgreSQL commits the cancelled WorkUnit revision and its
immutable command receipt in one transaction. A crash cannot leave Petra
claiming that cancellation occurred without the matching state transition, or
vice versa.

The receipt binds the exact expected WorkUnit ID, revision, and specification
hash; the resulting revision; protocol thread and run; reason; requesting
service actor; capability grant; trace; and time. Its explicit authority
boundary records that cancellation is operational only, changes no scientific
authority, and was not caused by a connection abort.

## Command behavior

```text
authenticated CancelWorkUnit command
  → lock WorkUnit + command ID + idempotency key
  → require exact running WorkUnit revision and specification
  → require the WorkUnit's service identity and capability grant
  → append cancelled WorkUnit revision
  → append immutable cancellation receipt in the same transaction
```

Exact redelivery returns the stored receipt and result without advancing the
WorkUnit again. Reusing either command identity with different input fails.
Stale references, wrong capabilities, wrong service identities, terminal
WorkUnits, and non-cancellable policies fail without a receipt or state change.

## Remaining boundary

The HTTP stop route still needs to resolve its protocol run to the durable
WorkUnit, persist this command, interrupt the active Codex turn, and close a
cancelled InteractionRun whose events can be replayed after restart. Merely
aborting an AG-UI delivery connection must continue to do none of those things.
