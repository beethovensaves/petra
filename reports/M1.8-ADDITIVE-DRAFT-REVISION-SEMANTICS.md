# M1.8 additive draft revision semantics

Status: pass for `M1.8-EV07`; `M1.8-W09`–`M1.8-W13` in progress

Scope: deterministic researcher edits, visible support staleness, and explicit revalidation

Date: 2026-09-04

## Outcome

Petra now has a model-free editing kernel for one or more exact DraftSpans. An
edit names the current span ID and exact text hash, supplies replacement text,
and creates the next immutable DraftArtifact revision under a human Actor. The
prior draft is not changed.

The new revision receives new content-addressed DraftSpan identities and Unicode
code-point ranges. Unchanged text keeps its prior provenance bases. Changed text
is explicitly marked as researcher language, retains its prior evidence bases
for inspection, adds the researcher basis, and makes that mapping stale rather
than silently inheriting support. Canonical citations are rebuilt against the
new span identities; bibliographic metadata is copied without invention.

## Support assessment

`DraftSupportAssessment@1.0.0` is a separate immutable, revisioned record over
one exact DraftArtifact, ProvenanceMap, and CitationBundle. It answers a question
the underlying records cannot answer by themselves after an edit: which span
support and citation links remain safe to reuse now?

The root assessment is created by the edit command. It exhaustively records
current and stale spans, exact provenance-basis snapshots, current, partially
stale, or stale citation links, validators, limitations, and a reuse decision.
Its contract fixes two boundaries:

- the assessment is not scientific evidence;
- the current assessment controls whether the draft can be reused as supported.

This avoids rewriting the immutable draft merely because a later validator ran,
and it avoids treating a successful validation as a new empirical finding.

## Explicit revalidation

Revalidation requires one reasoned, validator-backed pass or fail result for
every stale span, plus whole-draft validator results. It appends a contiguous
assessment revision with an exact parent hash. A passing result restores reuse
and clears citation-link staleness; a failed result remains non-reusable and
keeps the affected citation visible as stale. The edited DraftArtifact itself
remains an inspectable immutable record of its creation-time stale state.

Petra rejects wrong span hashes, duplicate or no-op replacements, edits layered
on already-stale provenance, missing revalidation results, pass/fail conflicts,
assessment ID or command rebound, non-contiguous lineage, and state that
disagrees with its span or citation outcomes.

## Executable evidence

One accepted and one rejected fixture pass through JSON Schema, generated
TypeScript, and strict Pydantic parity. Six core cases prove deterministic edit
replay, prior-revision preservation, Unicode-aware range shifts, selective
staleness, canonical citation relinking, caller immutability, assessment replay,
passing and failing revalidation, and fail-closed malformed state. The complete
repository gate passes with 591 always-on tests and seven expected
service-dependent skips: 276 contract, 210 core, 31 adapter, 15 retrieval, two
Neo4j, three S3, 29 server, and 25 Python tests.

## Remaining boundary

The semantics are intentionally storage-neutral in this increment. The next
stage will make edit commands idempotent, persist DraftArtifact revision 2 and
its new spans, map, citations, and root support assessment atomically, append
later assessment revisions without changing the draft, and prove restart
rehydration in PostgreSQL.
