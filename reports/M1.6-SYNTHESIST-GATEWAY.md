# M1.6 policy-first synthesist gateway

Date: 2026-09-03

## Outcome

Petra now has a provider-neutral `SynthesistGateway` between immutable evidence packets and any configured model. It compiles the exact ContextPacket and EvidencePacket into a bounded call, selects only an independently certified synthesist deployment, validates the response against the packet, and records immutable `model-request@1.1.0` and `model-call@1.1.0` objects.

The workbench's OpenAI deployment plugs into this gateway through the Codex subscription synthesist adapter. That adapter uses Codex App Server's managed ChatGPT OAuth session and has no API-key configuration. The optional Platform API adapter is not part of this route.

## Routing boundary

Before a provider sees context, the gateway requires:

- an active Project-scoped routing policy whose hash binds the complete policy;
- a permitted, healthy deployment with verified provider policy;
- compatible egress and data classes;
- structured-output support and sufficient context capacity;
- expected cost within the request budget; and
- an active synthesist RoleCertification for the exact deployment, contracts, language, modality, domain, and document class.

Extractor certification cannot satisfy this gate. If no synthesist certification matches, Petra writes a blocked ModelRequest and makes no provider call.

## Exact input and validation

The gateway records the exact packet hashes, rendered canonical records, evidence selections, SourceSpan selection orders, system and user messages, packet controls, model parameters, output schema, declared rights decisions, egress decision, and capability grant. Hashes bind the prompt profile, routing policy, parameters, exact input, call, and request. The gateway does not mint rights decisions or capability grants; their authoritative issue and revocation remain upstream responsibilities.

On return, the canonical output schema runs before Petra's packet-aware grounding checks. A plausible response that cites an object outside the EvidencePacket is retained as raw provider output for audit, marked `validation_failed`, and withheld as an accepted synthesis. Successful output is immutable and an identical logical request replays the recorded result without another provider call.

Subscription calls record token and per-call cost accounting as `unavailable` when Codex App Server does not report them. Petra does not infer or fabricate metered API costs for a ChatGPT subscription.

## Executable evidence

Four new core cases prove:

1. exact packet-to-call compilation, certified routing, validation, immutable recording, and idempotent replay;
2. rejection of an exact-looking evidence reference outside the packet;
3. refusal before invocation when no active exact synthesist certification exists; and
4. rejection of a certification whose hash does not bind its deployment and evaluation.

The complete repository gate passes with 513 always-on tests and six expected service-integration skips.

## Remaining gate

This stage implements the production routing and recording boundary, but does not activate GPT-5.6 Terra for the synthesist role. `M1.6-W14` remains open until the exact OAuth-backed deployment and prompt pass the frozen synthesist certification suite and then execute through this gateway. AG-UI streaming and response invalidation remain separate later stages.
