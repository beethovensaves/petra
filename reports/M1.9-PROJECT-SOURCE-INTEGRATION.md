# M1.9 Project source integration

- **Status:** Second live M1.9-W04 slice passed
- **Verified:** 2026-09-08
- **Design boundary:** Frozen presentation preserved; source data authority replaced
- **Depends on:** [Project shell integration](M1.9-PROJECT-SHELL-INTEGRATION.md)

## Result

The production Sources collection and source-reader routes now consume
authenticated `petra.project-source-view@1.0.0` records. They no longer look up
same-named reference sources or infer Project membership from repository-wide
scholarly records.

V020 adds a stable ProjectSource identity with immutable, contiguous revisions.
Each revision binds all of the following exactly:

- one Project and one registered source role from an exact ProjectDefinition
  revision;
- one Work revision, WorkVersion revision, and ordered set of Author revisions,
  including their canonical record hashes;
- one immutable ArtifactManifest and its record hash; and
- an active or excluded Project-link state, without changing canonical source
  identity or deleting the copy.

The read adapter follows that binding through the exact Artifact, linked
RightsDecision, newest immutable ParsedDocument available in the same database
snapshot, StructuralBlock, and SourceSpan. It returns explicit identity, copy,
rights, representation extent, deterministic preview, linked Claim and
Assertion counts, and authority position. Collection and detail reads each use
one read-only repeatable-read transaction.

The server validates every outgoing view against the canonical contract. The
workbench maps the view into the frozen `SourceRecord` presentation model;
source title, creator, revision, copy, extent, rights, locator, excerpt, and
downstream use now come from authority records.

## Profile boundary

`project-source@1.0.0` is explicitly discriminated as
`scientific_work_version`. It is the implemented M1 scholarly-source
specialization, not Petra's universal source ontology. The shared Project shell
still resolves source terminology through ProjectDefinition, while a future
writing, code, dataset, or other profile may add its own typed source binding
without being forced through scholarly WorkVersion or Author semantics.

This slice therefore proves the existing M1 scientific path only. It does not
claim `UX1.3-AC01` paired-profile conformance, general file/link intake, source
reuse across Projects, external editing, GitHub integration, or managed-folder
and `.petra` archive behavior.

## Failure behavior

- An unregistered source role, substituted ProjectDefinition, unresolved exact
  identity revision, mismatched Author order, or copy from another WorkVersion
  fails before commit.
- One immutable copy can have only one stable ProjectSource identity inside a
  Project. Exact retries are idempotent; rebound or skipped revisions fail.
- A source requested through another Project returns
  `PROJECT_SOURCE_NOT_FOUND`; no similarly named or globally visible record is
  substituted.
- A verified copy without a ParsedDocument reports identity-only coverage. A
  copy whose RightsDecision forbids parsing reports restricted coverage.
- Parsed records report complete or partial coverage from their recorded
  quality state. The preview identifies its exact block, span, locator, and
  verification state.
- The existing Add and Process controls remain visibly unavailable because this
  slice adds authorized reads, not browser-owned mutation or processing
  commands.

## Frozen-design treatment

galleries and component tests retain their neutral examples. Only production
route loaders and their data adapters changed.
