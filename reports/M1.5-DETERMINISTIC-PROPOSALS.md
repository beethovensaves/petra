# M1.5 deterministic evidence proposal report

Status: pass  
Scope: `M1.5-W01`–`M1.5-W06`  
Date: 2026-09-02

## Outcome

Petra now converts exact passages from one immutable document parse into
portable Claim–`ASSERTS` proposal pairs without using a model. The deterministic
path is the oracle for later model extraction: it fixes the output shape,
identity rules, independent source checks, quarantine boundary, and expected
negative-control behavior before a model can add variability.

On the pinned Wilkinson et al. (2016) paper, Petra admits two independently
verified pairs into quarantine:

| Role | Canonical proposition | Exact source location |
| --- | --- | --- |
| Primary | The FAIR Principles emphasize enabling machines to find and use data automatically. | Page 1, `source_span_4Q7FRK7AD4SAVJKZ570S109AJ2` |
| Qualification | The FAIR Principles are not themselves a standard or specification. | Page 5, `source_span_5GKVKGPBGR44A9N0MXG2J2YEVP` |

A deliberately plausible claim that the FAIR Principles guarantee reproducible
scientific results cites a fabricated SourceSpan. Admission rejects it with
`SOURCE_SPAN_NOT_IN_BUNDLE`, and atomic pair registration proves that its Claim
does not survive after its Assertion fails.

## Boundary implemented

| Boundary | Executable behavior |
| --- | --- |
| Portable output | `petra.evidence-proposal-bundle` is an accepted Draft 2020-12 schema with generated TypeScript declarations and a Python smoke representation. |
| Immutable source | The bundle identifies one document-parse bundle, ParsedDocument, source Artifact and hash, WorkVersion, and source scope. Its canonical content hash is rechecked before any candidate is evaluated. |
| Extraction identity | Deterministic proposals record extractor name/version, recipe hash, stable extraction-run identity, and start/completion observations. The contract already requires model request, call, deployment, prompt, parameter, and ContextPacket identities when `model_extraction` is used later. |
| Candidate meaning | Every candidate carries an explicit role, exact source quote and text hash, Claim, paired `ASSERTS` Assertion, SourceSpan IDs, warnings, and scientific scope. |
| Independent validation | Admission ignores the authority implied by extractor-declared validator results and directly checks quote hashes, reciprocal span/block references, source bytes, parser run, pages, page parse state, source verification, WorkVersion, scope, and edge endpoints. |
| Atomicity | Claim and Assertion proposals register as one in-memory transaction. Any failure restores both registries and their revision histories. Candidates in one proposal bundle have independent visible outcomes. |
| Authority | Successful candidates remain revision-1 `machine_checked` quarantine records. The extractor and admission service have no promotion operation. |
| Failure | Invalid bundle identity or content fails the whole envelope. Unsupported individual candidates return a typed rejection without preventing independent supported candidates from entering quarantine. |

## Reproducibility proof

Run:

```sh
npm run models:docling
npm run test:evidence-proposals:integration
```

The integration command verifies the four pinned Docling model assets, builds
the current TypeScript packages, parses the exact lawful PDF with network access
blocked, passes the M1.4 document verifier, validates the evidence proposal
against the shared registry, and exercises independent admission. The observed
result is:

```text
source quality: partial
proposed candidates: 3
admitted quarantine pairs: 2
rejected candidates: 1
negative-control error: SOURCE_SPAN_NOT_IN_BUNDLE
negative-control Claim persisted: false
remote model calls: 0
```

Stable IDs are derived from immutable parse, recipe, and candidate identities.
Repeated construction in the unit suite produces byte-equivalent proposal
objects. TypeScript's deterministic ID helper is pinned against the Python
worker algorithm.

## Known limits and next gate

This stage does not yet persist the proposal bundle as an Artifact, register the
admitted pair through a single PostgreSQL repository transaction, show a review
inspector, promote evidence, or project a new trusted relation. Existing
PostgreSQL ChangeSet, Approval, event/outbox, and Neo4j projection primitives
remain unchanged.

The next M1.5 stage is `M1.5-W07`–`M1.5-W12`: assemble a review projection that
shows source, scope, origin, and validation together; represent accept, reject,
and correct decisions; apply each independently reviewable mutation through the
same durable command path; expose graph catch-up; and prove compensating
reversal without deleting history. AG-UI mediation follows that direct command
proof and cannot become a second authority path.
