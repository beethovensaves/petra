# M1.6 grounded-response identity and invalidation

Status: pass

Scope: `M1.6-W19` and the semantic portion of `M1.6-AC04`

Date: 2026-09-04

## Outcome

Petra now has a revisioned `GroundedResponse` record for one displayed scientific answer. The record binds immutable Markdown bytes to their exact Artifact, ContextPacket, EvidencePacket, authority snapshot, selected evidence dependencies, successful synthesist ModelRequest and ModelCall, completed InteractionRun, successful WorkUnit, model-output hash, deterministic cache key, and persisted terminal time.

This is an operational derivative, not scientific authority. Registering or invalidating it creates no Claim, Assertion, Approval, or ChangeSet.

## Why this is not a DraftArtifact

`DraftArtifact` belongs to M1.8's research-composition layer: it will model editable prose, provenance maps, citations, renderers, and researcher revisions. A displayed assistant answer needs a narrower runtime identity now. Reusing `DraftArtifact` would prematurely couple interaction persistence to later paper-writing semantics.

The immutable bytes therefore remain a normal `Artifact` with `artifact_kind: run_output`. `GroundedResponse` supplies the missing operational bindings and cache state. Its revisions never rewrite or delete the Artifact.

## Registration boundary

The storage-neutral reference registry refuses a terminal response unless all of the following are exact:

- Artifact ID, media type, byte count, SHA-256, creator, and supplied bytes;
- registered ContextPacket, EvidencePacket, and shared snapshot;
- an exhaustive, duplicate-free dependency list equal to every selected EvidencePacket object;
- canonical synthesist request and call hashes, selected deployment and role certification, packet input, prompt, parameters, output contract, selected context, passing validators, and structured output hash;
- completed InteractionRun correlation and successful `petra.synthesis.grounded@1.0.0` WorkUnit correlation; and
- terminal ordering after every bound execution record.

The cache key hashes the complete pre-execution synthesis need while omitting the logical request ID and terminal result. Equivalent retries can reuse a still-valid answer, while a change in packets, snapshot, objective, outbound selection, prompt, parameters, policy, or selected route misses.

## Reversal behavior

When a later `change_set.applied` or `change_set.reverted` event changes a Claim or Assertion on which a response depends, Petra creates a new `GroundedResponse` revision:

```text
GroundedResponse revision 1: reusable
  └─ immutable response Artifact
  └─ exact selected Claim, Assertion, and SourceSpan

later scientific-authority event
  ↓

GroundedResponse revision 2: invalidated
  └─ same immutable response Artifact
  └─ parent revision and parent content hash
  └─ exact event and ChangeSet cause
  └─ affected dependency IDs
```

Events at or before the answer's snapshot cannot invalidate it. Events from another Project or events that do not touch a dependency leave it reusable. Exact event replay is idempotent; reuse of an event ID with different content fails. Registration replay still resolves revision 1 after later invalidation, but the cache lookup returns no reusable answer.

The implementation builds and validates every affected revision before committing any of them in memory. The PostgreSQL adapter must preserve that all-or-nothing event behavior.

## Executable evidence

Seven domain cases prove:

1. exact immutable registration and idempotent replay;
2. atomic rejection of changed response bytes;
3. atomic rejection of a hidden evidence dependency omission;
4. refusal of merely similar model and interaction bindings;
5. revisioned invalidation from a real compensating scientific reversal while preserving revision 1 and the Artifact identity;
6. exact authority-event replay and conflicting event-ID refusal; and
7. continued cache reuse for unrelated and pre-snapshot events.

The canonical schema also has accepted and rejected cross-language fixtures. The rejected fixture proves that an `invalidated` state cannot omit its event causes and affected dependencies.

The complete repository gate passes with 537 always-on tests and six expected service-integration skips. That includes 252 contract-parity tests and 188 storage-neutral core tests.

Until that passes, `M1.6-AC04` and the persistence portion of `M1.6-AC07` remain open.
