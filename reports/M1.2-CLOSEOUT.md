# M1.2 closeout — authority and immutable bytes

Date: 2026-09-02  
Result: pass

M1.2 establishes Petra's persistence boundary before the first real Neo4j
projection. PostgreSQL is authoritative for identities, revisions, commands,
events, projection control, durable work, and interaction history. S3-compatible
storage is authoritative for immutable bytes. Neither Neo4j nor AG-UI may write
scientific authority.

## Storage proof

The `@petra/s3` adapter uses the official AWS S3 SDK and a disposable SeaweedFS
4.41 service. Seven real-service cases cover streaming hashes and byte counts,
content-addressed publication, complete read verification, duplicate
convergence, failed-stage cleanup, warning preservation, missing/corrupt
objects, and bounded garbage collection. The standalone runner binds a dynamic
loopback port and removes every labeled container, network, and temporary volume
in both success and failure paths.

S3 copy provides atomic visibility for one final object key. It cannot make the
S3 and PostgreSQL operations one distributed transaction. Petra therefore makes
the object available first and closes PostgreSQL admission unless the final
object can be inspected exactly. Hosted retention, versioning, backups, and
object-lock policy remain deployment responsibilities.
