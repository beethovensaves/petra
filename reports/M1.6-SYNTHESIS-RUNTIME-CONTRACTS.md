# M1.6 synthesis runtime contracts

Date: 2026-09-03

## Outcome

Petra now has immutable runtime records for the bounded synthesist role without changing the accepted extractor contracts. `model-role-certification`, `model-request`, and `model-call` each gain a `1.1.0` variant that is explicitly bound to `evidence-packet@1.0.0` input and `model-synthesist-output@1.0.0` output.

This is the contract foundation for `M1.6-W14`; it does not mark a real model deployment as certified or complete the configured call.

## Boundaries fixed by the contracts

- A synthesist certification is independent from extractor certification.
- A request identifies the exact ContextPacket and EvidencePacket, every outbound canonical object revision and hash, the rights decisions, redactions, purpose, budget, routing decision, and terminal validation result.
- A physical call records the selected deployment observation, exact rendered context selections, structured output, validator results, timing, usage accounting, and cost accounting.
- A successful call must contain the strict synthesist output and cannot contain a failure; every unsuccessful call must contain a failure and cannot contain accepted output.
- The records contain neither credentials nor hidden reasoning.

## OpenAI authentication boundary

The intended OpenAI execution route remains Petra's Codex App Server provider using Codex-managed ChatGPT OAuth. It does not require `OPENAI_API_KEY`, does not accept an API key through Petra, and does not read Codex credential storage. The Platform API adapter remains optional and is not part of the individual-workbench path.

The next runtime slice will invoke the synthesist through the existing managed subscription sidecar, run its separate frozen certification suite, and record these `1.1.0` contracts.
