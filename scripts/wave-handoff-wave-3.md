# Automated Wave 3 handoff

This execution packet is subordinate to Petra's accepted decisions, graph model,
runtime contracts, implementation roadmap, frozen UX brief, and UX runtime
architecture disposition. It coordinates bounded work; it does not create new
product authority.

## Outcome

Complete backend Wave 3: graph, History, action, and operational control.

The authoritative exit gate is:

> One exact action can start bounded Work, preserve interruption state, return a
> result, and expose its history and eligible recovery without client-side
> authority calculations.

## Current boundary

- The bounded current relationship read is already live.
- The backend History spine, retained traversal, dependency impact, exact
  recovery assessment, compensation preview/plan/execution, and supported
  selected-event historical destination are implemented.
- The design branch has mapped `project-history-episode-view@1.2.0` into the
  frozen History regions. The currently supported episode-event union has no
  additional target family that justifies widening that destination registry.
- The bounded Wave 3 SuggestedAction increment is complete. One exact action
  starts bounded Work, preserves an interrupted delivery, returns its exact
  result, exposes canonical Work History and server-owned recovery, and replays
  the retained response after restart through the production workbench client
  and shared frozen presentation controllers.
- The cumulative proof renders the direct and conversational action regions
  from live ready and terminal runtime authority without fixture fallback.
  Broader action families and controls remain governed by later accepted work.

## Default implementation order

1. Implement the smallest server-owned, Project-scoped, authenticated,
   revisioned SuggestedAction preview/readiness slice derived from existing
   authority. Do not start Work in the first slice.
2. Map and integrate each accepted action slice through the frozen design
   boundary without creating client authority.
3. Add exact SuggestedAction invocation through an existing Work-compatible
   command path, including stale regeneration, idempotency, capability, result,
   History, and recovery bindings.
4. Add the smallest typed Work steering and Project-control transitions required
   by the exit gate. Do not imply generic pause/resume or cancel shared Work.
5. Bind the accepted History/action/recovery paths into the frozen interface and
   run the cumulative live Wave 3 proof.

Change this order only when repository evidence identifies a concrete dependency,
and record the reason in the ordinary roadmap/report authority.

## Permanent constraints

- Process exactly one bounded slice per worker turn, verify it, commit it, push
  it, and hand off.
- Never create a second History, Work, action, recovery, or authority ledger.
- Preserve exact Project, Actor, command, event, target, snapshot, definition,
  Work, result, receipt, and semantic-destination identities wherever applicable.
- Direct and conversational action invocation must converge on the same Petra
  command.
- Keep graph-navigation history and unsent presentation state client-local.
- Do not infer global cross-family ordering, effect, reversibility, authority,
  readiness, cost, or semantic meaning.
- The current version is single-user, but Actor identity and command
  authorization remain mandatory.
- Do not implement generic Undo, reversal of a reversal, multi-step compensation,
  multi-user behavior, external filesystem editing, or a universal setting
  mutation.
- Use the pinned Node 24 toolchain. Run complete verification and real
  PostgreSQL integration whenever the slice changes PostgreSQL behavior.
- The design worker owns frozen components, CSS, browser routes, presentation
  fixtures, and accessibility evidence. The backend worker must not change them
  unless the design handoff explicitly requests a bounded integration.
- The design worker must not edit runtime contracts, server, persistence, or
  backend authority. It proposes those changes through the handoff.
- Leave the known untracked design image and PDF untouched.

## Stop conditions

Return `needs_user` instead of guessing when a choice would change product
meaning, architecture, authority, the frozen information hierarchy, or the wave
exit gate. Return `blocked` for a failed verification gate, unavailable required
service, branch divergence, merge conflict, approval failure, authentication or
usage limit, or any unsafe/ambiguous repository state. Do not commit partial or
unverified work.

Declare `wave_complete` only after the exact exit gate is demonstrated live,
both repositories' required work is committed and pushed, the frozen interface
uses runtime authority without fixture fallback for the demonstrated path, and
the relevant reports record the evidence and remaining omissions.
